# 保护与降级策略

Tidy 的保护机制只能降低非核心能力或提高可恢复性，不能静默改变数据语义、覆盖用户状态或借用不可控的宿主环境。

## 必须明确失败

- **模型选择**：CLIP 只由 `TIDY_CLIP_MODEL_ID` 决定，默认固定为 `jinaai/jina-clip-v2`。本机是否残留某个模型目录不能改变模型。
- **模型一致性**：server 与 ai-service 报告的模型标识不一致时，CLIP 任务停止并给出可操作错误，禁止把不同向量空间混写到数据库。
- **配置损坏**：仅当 `config.json` 不存在时创建默认配置。文件存在但无法读取、解析或校验时保留原文件并报错，禁止覆盖为默认值。
- **正式包运行时**：桌面正式包缺少随包 Node 或 ai-service 时启动失败，禁止静默借用系统 Node/Python。
- **数据库迁移**：结构迁移和必要回填失败时中止启动，禁止吞错后带着未知的半迁移状态继续运行。

## 允许降级

- **网络盘监听**：UNC、映射网络盘和可移动盘不使用不可靠的递归实时监听，改为有状态展示的周期扫描。
- **端口占用**：首选本地端口被占用时选择空闲端口；实际端口写入诊断信息，且不改变持久化语义。
- **派生文件**：个别损坏图片无法生成缩略图、视频封面或可选元数据时记录具体文件与错误，其他资产继续处理。
- **缓存与日志维护**：缓存写入、日志轮转或更新提示失败不能破坏文件操作与数据库一致性，但必须尽可能记录上下文。

## 数据目录边界

- 开发模式默认直接使用仓库根 `data/`，不复制数据库。
- 正式桌面版默认使用 Electron `userData/data`。
- 需要其他位置时使用桌面专用的 `TIDY_DATA_DIR`；不会通过通用环境变量或探测旧目录自动迁移。
- 从 MSIX 宿主（例如 Codex）启动安装/迁移流程时，必须识别 Windows AppData 虚拟化；不得把宿主的 `LocalCache/Roaming` 误认成用户真实 AppData。
